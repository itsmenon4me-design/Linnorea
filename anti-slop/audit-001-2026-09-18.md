# Responsive UI audit

Audit date: 2026-09-18

## Scope

Tested at viewport widths 320, 375, 768, 1024, and 1440 pixels:

- Home
- About
- Projects
- Project detail
- Services

The development server was tested at `http://localhost:3131`.

## Findings

1. **LOW - No page-level horizontal overflow found**
   - The tested pages kept `scrollWidth` equal to the available document width at all tested viewport sizes.
   - This confirms the current responsive foundation works for the tested routes.

2. **LOW - Carousel content intentionally exists outside the viewport**
   - Home and Services contain off-screen carousel or scroller items.
   - This is expected for horizontal browsing, but it must remain clipped by the scroller and reachable through drag, swipe, keyboard, or visible controls.
   - No change made because this is part of the intended interaction.

3. **RESOLVED - Services media now falls back when playback fails**
   - Mux playback produced `MediaError` and `bufferAppendError` messages during the audit.
   - The page still rendered and the layout remained usable.
   - The Hero and Studio Visual components now stop retrying a failed video and keep the poster or configured image visible instead.
   - A follow-up browser check confirmed the Services page remained visible, had no page overflow, and did not emit the previous Mux media error messages during the test window.

4. **RESOLVED - Hero no longer preloads multiple Mux videos at once**
   - The Hero previously set the active and next slide to `preload="auto"` and also started managed preload operations for every mounted player.
   - The active slide is now the only automatically preloaded video. Other slides load on demand when they become active or are selected during a drag.
   - A follow-up Home check showed the active player reached `readyState: 4`, inactive players stayed unloaded, and no Mux media error was emitted during the test window.

5. **LOW - External browser integrations produce console noise**
   - The browser blocked the Google Cast sender script due to the current Content Security Policy.
   - Requests to the external Litix endpoint were aborted.
   - These messages did not create visible layout failures during the audit.

6. **LOW - Product remains visible in the public navigation**
   - Product is hidden from the Sanity Studio structure, but the public header still contains a Product link.
   - The Product route exists, so this is not a dead link. It should be intentionally kept or removed when the Product scope is finalized.
   - No change made because the current request was an audit only.

## Responsive status

- 320px mobile: PASS for page-level overflow and basic text wrapping.
- 375px mobile: PASS for page-level overflow and mobile header layout.
- 768px tablet: PASS for page-level overflow.
- 1024px laptop/tablet landscape: PASS for page-level overflow.
- 1440px desktop: PASS for page-level overflow and max-width containment.

## Audit conclusion

The responsive foundation is already present and passed the tested layout checks. The site is not yet fully clean from a browser-console perspective because of Mux media errors and external integration warnings. No code was changed during this audit.
